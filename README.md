# AWG Telegram Bot

Telegram-бот для установки AmneziaWG 3.1 на собственный VPS и выдачи отдельных `vpn://` профилей.

## Возможности

- owner задаётся через `OWNER_TELEGRAM_ID`;
- мастер `/server` принимает VPS, SSH user и пароль, устанавливает Docker и userspace AWG 3.1;
- одно статусное сообщение обновляется каждые 10 секунд;
- `/allow ID`, `/deny ID`, `/users` управляют ACL;
- `/newkey [название]` создаёт отдельный peer и совместимый с AmneziaVPN `vpn://` профиль;
- `/deny` отзывает все активные peer пользователя;
- SSH-пароль зашифрован Fernet-ключом в persistent volume, сообщение с паролем удаляется;
- SSH host key закрепляется после первого подключения (TOFU).

## Запуск

```bash
cp .env.example .env
# заполнить TELEGRAM_BOT_TOKEN и OWNER_TELEGRAM_ID
docker compose up -d --build
docker compose logs -f bot
```

Затем owner отправляет боту `/server`. Поддерживается VPS Debian/Ubuntu с `sudo`; учётная запись должна иметь право выполнять sudo с указанным паролем. На VPS должны быть доступны GitHub, Docker Hub и репозитории пакетов.

После установки owner получает первый VPN-профиль. Термин «администраторский профиль» здесь означает первый профиль владельца; права управления VPS в `vpn://` намеренно не помещаются. Администрирование и отзыв peer выполняются командами бота.

## Важные замечания

- Установка создаёт `/opt/awg-bot` и контейнер `awg-bot-server` на VPS. Существующие контейнеры Amnezia она не удаляет.
- По умолчанию используется UDP 443 и подсеть `10.8.1.0/24`; значения меняются в `.env`.
- `AWG_GO_REF` и `AWG_TOOLS_REF` лучше закрепить на проверенных git-тегах/ветках перед production-развёртыванием. Значение `master` удобно для первого теста, но не обеспечивает воспроизводимую сборку.
- `vpn://` содержит приватный ключ. Telegram-боты не используют end-to-end encryption; для повышенной защиты следует заменить отправку ключа на одноразовую HTTPS-выдачу.
- Формат `vpn://` — внутренний формат AmneziaVPN. Перед production необходимо проверить импорт на целевых версиях Android/iOS.
